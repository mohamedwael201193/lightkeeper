## Q4-chainmcp

**Q:** What is the Pharos Chain MCP and which read tools does it expose for an AI agent?

**Goal:** building an AI agent on Pharos

**A (verbatim, 27.61s):**

> The **Pharos Chain MCP** connects MCP-compatible AI clients to Pharos chain data and operations through natural-language requests. Its hosted endpoint is `https://mcp.pharos.xyz/mcp` using Streamable HTTP; it requires no API key and targets chain ID `1672` (`0x688`).
> 
> Its read tools are:
> 
> * **Chain and blocks:** `get_chain_info` (chain ID, client version, latest block), `get_block_number`, `get_block`, `get_gas_price`
> * **Accounts and transactions:** `get_balance` (native PROS), `get_transaction_count`, `get_transaction`, `get_transaction_receipt`
> * **Contracts and logs:** `eth_call` (read-only contract calls), `estimate_gas`, `get_code`, `get_storage_at`, `get_logs` (event logs; maximum 1,000 blocks per call)
> 
> `send_raw_transaction` is also exposed, but it broadcasts an already-signed transaction rather than reading chain data. See [Pharos MCP](/tooling-and-infrastructure/mcp) for setup and tool details.
>

## Q5-getlogs

**Goal:** building an on-chain event monitor

**A (verbatim, 76.21s):**

> For direct Pharos JSON-RPC `eth_getLogs`, the range limit is **100 blocks when rate limiting is enabled**, or **10,000 blocks as a fallback cap**. > 
> If you’re using the Pharos MCP server’s `get_logs` tool instead, its limit is **1,000 blocks per call**.

## Q6-skillengine

**Q:** How do I install, build and publish a skill with the Pharos Skill Engine?

**Goal:** publishing an agent skill

**A (verbatim, 71.18s):**

> The workflow has two parts: build and test the Pharos Skill, then upload it as a Service Agent on Anvita Flow.
> 
> 1. **Install the Skill Engine and Foundry.** Unzip the Skill Engine package, enter its directory, and install Foundry if needed:
> 
>    ```bash
>    unzip pharos-skill-engine-0.1.0.zip
>    cd pharos-skill-engine-0.1.0
> 
>    which cast || (curl -L https://foundry.paradigm.xyz | bash && source ~/.zshenv && foundryup)
>    cast --version
>    forge --version
>    ```
> 
>    Configure your wallet with `PRIVATE_KEY` as an environment variable. Never put the key in a script or commit it to git. See [Pharos Skill Engine](/tooling-and-infrastructure/pharos-skill-engine-guide).
> 2. **Build the skill.** Add the contract to `assets/<skill>/` and `src/<skill>/`, then run `forge build`. Write `references/<skill>.md` with command templates, parameters, output parsing, and error handling. Add natural-language intent rows to the Capability Index in `SKILL.md`.
> 3. **Test and prepare the package.** Follow the Skill Engine’s publishing checklist: compile, deploy and verify on testnet, and check that every operation has instructions. Package the skill folder itself as a `.zip`. It must contain an uppercase `SKILL.md` at its root folder, with `name` and `description` frontmatter; `name` must match the folder name exactly.
> 4. **Publish on Anvita Flow.** Register at [Anvita Flow](https://flow.anvita.xyz/home), open the [Developer Console](https://flow.anvita.xyz/service-agents), and select **Create A Managed Service Agent**. Upload the zip, configure the service strategy and runtime, run a successful debug session, complete the Agent Card, and submit for review. It is live after approval, when its status shows **Published / Running**. See [Publish Service Agent](/tooling-and-infrastructure/overview/publish-skill-af).
>
