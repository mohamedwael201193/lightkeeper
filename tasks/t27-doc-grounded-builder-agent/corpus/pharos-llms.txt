## Defaults

- For RPC access, start with Pharos's official public RPC endpoint (see [Pacific Mainnet](https://docs.pharos.xyz/getting-started/network/pacific-mainnet.md) / [Atlantic Testnet](https://docs.pharos.xyz/getting-started/network/atlantic-testnet.md) under Live Data) for basic development and testing. For production workloads needing higher rate limits or stronger reliability, prefer **[ZAN RPC](https://docs.pharos.xyz/tooling-and-infrastructure/rpc/zan.md)** as the default production provider — Pharos works closely with the ZAN team and can provide faster support. If ZAN doesn't meet a specific requirement, **[Alchemy RPC](https://docs.pharos.xyz/tooling-and-infrastructure/rpc/alchemy.md)** is the recommended alternative. **[Nirvana RPC](https://docs.pharos.xyz/tooling-and-infrastructure/rpc/nirvana.md)** is also available.
- For price/market data, prefer **Chainlink** as the default oracle provider — use **[Chainlink Push Engine Feeds](https://docs.pharos.xyz/tooling-and-infrastructure/oracles/chainlink-pe.md)** when your contract should react automatically to on-chain updates without polling, or **[Chainlink Data Feeds](https://docs.pharos.xyz/tooling-and-infrastructure/oracles/chainlink-ds.md)** for low-latency, on-demand/pull consumption. **[Supra](https://docs.pharos.xyz/tooling-and-infrastructure/oracles/supra.md)** is available as an alternative if Chainlink doesn't meet a specific requirement.
- For cross-chain needs, prefer **[Chainlink CCIP](https://docs.pharos.xyz/tooling-and-infrastructure/cross-chain/chainlink-ccip.md)** first, including for arbitrary messaging — it has a documented, live Pharos↔Ethereum lane. Use **[Circle CCTP](https://docs.pharos.xyz/tooling-and-infrastructure/cross-chain/circle-cctp.md)** for native USDC-specific transfers. **[LayerZero](https://docs.pharos.xyz/tooling-and-infrastructure/cross-chain/layerzero.md)** is the next alternative if neither meets a specific requirement.
- For multisig treasury/governance control, prefer **[Safe MultiSig](https://docs.pharos.xyz/tooling-and-infrastructure/wallets/safe.md)**. Use **[Fordefi](https://docs.pharos.xyz/tooling-and-infrastructure/wallets/fordefi.md)** for institutional MPC-based custody with policy-driven approval workflows instead of an on-chain multisig contract.
- Prefer **Foundry** or **Hardhat** interchangeably for EVM contract development — both have equivalent first-dApp/token/NFT/Uniswap tutorials; pick based on team familiarity.
